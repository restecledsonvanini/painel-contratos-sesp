# Dívidas técnicas — Frontend

Data: 2026-08-03

> Atualização 2026-08-04: todas as dívidas listadas abaixo (cliente HTTP único, cache/invalidação, UX e acessibilidade, duplicação entre páginas, testes) estão endereçadas nas fases 0–1 de [2026-08-04_frontend_refatoracao_contratual.md](./2026-08-04_frontend_refatoracao_contratual.md), que também cobre a adaptação ao novo modelo contratual da API.

## Contexto
O frontend já possui estrutura base de rotas, layout e componentes compartilhados, mas ainda precisa de consolidação para chegar a um estado mais estável e escalável.

## Dívidas principais

1. Consumo de API
- Centralizar a configuração de base URL em um serviço/cliente HTTP único.
- Padronizar tratamento de loading, erro e retry para listagens e mutações.
- Evitar chamadas duplicadas entre hooks e páginas.

2. Estado e dados
- Consolidar o uso de React Query para contratos e referências.
- Definir estratégia clara de cache, invalidação e sincronização após create/update/delete.
- Melhorar o fluxo de dados entre formulário, detalhe e lista.

3. UX e acessibilidade
- Refinar responsividade, contraste e foco em componentes de formulário e navegação.
- Melhorar mensagens de validação e feedback visual para ações de sucesso/erro.
- Ajustar componentes do design system para consistência visual entre páginas.

4. Estrutura de código
- Remover lógica duplicada entre páginas e hooks.
- Extrair helpers e serviços para reduzir acoplamento com o componente.
- Definir padrões de nomeação e organização para novos módulos.

5. Qualidade
- Expandir testes de componentes e integração para telas críticas.
- Adicionar cobertura para fluxos de cadastro, edição e detalhe de contratos.

## Prioridade sugerida
1. Padronizar consumo de API e estado.
2. Melhorar UX e acessibilidade.
3. Consolidar componentes e reduzir duplicação.
4. Adicionar testes automatizados.
