# Plano de Implementação — Sistema Hub de Inteligência Contratual

Data: 2026-07-29

## Objetivo
Construir uma UI competente para gestão contratual com dashboard, formulário de lançamento de contratos e suporte a campos customizáveis. O design system deve focar nas cores principais `#0d6efd` e `#fff`, e oferecer toggle de light/dark mode.

## Status atual
- Monorepo funcional com `apps/web`, `apps/api`, `packages/schema`, `packages/db`.
- API conta com `POST /contracts` válido e validação Zod.
- Frontend básico com rotas para dashboard, lista e formulário.
- Tailwind agora compila, mas o layout ainda precisa ser alinhado à referência visual.
- Não há formulário progressivo, dashboard final ou menu lateral no padrão desejado.

## O que falta implementar
1. **Design system completo**
   - `packages/ui` com tokens, cores, tipografia, espaçamentos e variantes light/dark.
   - componente `ThemeToggle` e `ThemeProvider`.
2. **Layout e navegação**
   - `DashboardLayout` com sidebar, header e área de conteúdo.
   - páginas: Dashboard, ContractsList, ContractForm, ContractDetail.
3. **Dashboard de contratos**
   - cards de métricas (total contratos, valor total, vencimentos próximos).
   - visualização de timeline contratual conforme lei 14.133/2021.
4. **Formulário de cadastro avançado**
   - seções: dados principais, datas/valores, aditivos, campos customizáveis.
   - possibilitar criação de novos campos pelo usuário.
5. **Backend adicional**
   - endpoints `GET /contracts`, `GET /contracts/:id`, `PUT /contracts/:id`, `DELETE /contracts/:id`.
   - endpoint de relatórios/saúde contratual.
6. **Campos customizados**
   - armazenar `metadata` ou `customFields` no contrato.
   - renderizar esses campos no detalhe e permitir edição.

## Prioridade inicial
1. Criar design system e tema.
2. Implementar layout global com sidebar + header.
3. Desenvolver Dashboard MVP.
4. Criar lista de contratos com filtros básicos.
5. Criar formulário de contrato com campos customizáveis.
6. Adicionar API de listagem e detalhe de contratos.

## Critério de partida
Podemos começar imediatamente se:
- você aceitar que o primeiro sprint será de UI/UX e estrutura de layout;
- o backend continuará evoluindo em paralelo com os endpoints de listagem e detalhe;
- estiver OK usar `#0d6efd` e `#fff` como base do tema e suportar dark mode desde o início.

## Conclusão
Sim, podemos começar. A base técnica já existe, mas é preciso avançar na camada visual, no design system e nas páginas de dashboard e contrato antes de considerar o produto utilizável.
